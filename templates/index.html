📐 Conceptual ER & Relational Model
Complete Entity-Relationship mapping for the academic system

1. Strong Entities:

  • STUDENT: Attributes (student_id [PK], name, roll_no, class_name, division).
  • SUBJECT: Attributes (subject_id [PK], subject_name [UNIQUE], max_marks [CHECK > 0]).

2. Associative Entity (M:N Resolution):

  • MARKS: Resolves Many-to-Many relationship between Student and Subject.
  • Foreign Keys: student_id [FK → student], subject_id [FK → subject].
  • Constraint: UNIQUE(student_id, subject_id) prevents duplicate evaluations.
  • Referential Action: ON DELETE RESTRICT ON UPDATE CASCADE prevents orphaned records.

3. Normalization (3NF Justification):

  • 1NF: Every column contains atomic scalar values (no repeating groups).
  • 2NF: In 1NF and no non-prime attribute depends on a proper subset of any candidate key.
  • 3NF: In 2NF and no transitive functional dependencies exist ($X \to Y$ holds only if $X$ is a superkey).
🛡️ PostgreSQL Constraints & Triggers
Active integrity enforcement running in PostgreSQL 18

1. PL/pgSQL Trigger: Marks Upper Bound Check

CREATE OR REPLACE FUNCTION check_marks_within_max()
RETURNS TRIGGER AS $$
DECLARE v_max_marks NUMERIC;
BEGIN
  SELECT max_marks INTO v_max_marks
  FROM subject WHERE subject_id = NEW.subject_id;
  IF NEW.marks_obtained > v_max_marks THEN
    RAISE EXCEPTION 'Score % exceeds max %',
      NEW.marks_obtained, v_max_marks;
  END IF;
  RETURN NEW;
END; $$ LANGUAGE plpgsql;

2. PL/pgSQL Trigger: Maximum Marks Reduction Guard

-- Prevents a professor from accidentally lowering max_marks
